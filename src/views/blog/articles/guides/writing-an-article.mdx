An article is an MDX file — Markdown with the app's components in it — compiled when the app is built. Writing one takes four steps.

## 1. The file

Write `src/views/blog/articles/<path>.mdx` — for example `components/my-view.mdx`. Its address is then `/blog/components/my-view`. A Hebrew version, when there is one, is `<path>.he.mdx` beside it; without one, the English is shown under Hebrew too, left to right.

Start the document below its title: the page shows the title as its heading, so use `##` and `###` for sections, never `#`.

## 2. The registry

Add the article to `BLOG_ARTICLES` in `src/views/blog/articles.ts`: its path, its title and a one-line summary, each in English and Hebrew. A new folder is an entry in `BLOG_FOLDERS` there — folders nest, `guides/front-page` inside `guides`. The sidebar's Blog folder and the index pages read both lists.

## 3. The routes

Give the article its line in `src/routes.tsx`, beside the other articles, and one in `e2e/a11y/routes.ts`, so the browser accessibility pass visits it. `src/views/blog/articles.test.ts` fails when a file, the registry and the routes disagree.

## 4. What it may embed

The components are used by name, with no `import`:

- `<BoardRow>` — embeds side by side;
- `<CollectionGameBoard game="/library/<c>/<n>" />` — a Library game;
- `<RepertoireBoard _id="/repertoires/<id>" fallback="e4-white" />` — a repertoire;
- `<CollectionCard _id="/library/<c>" showGame="1" />` — a collection;
- `<StoredGameEmbed reference="…" />` — any stored game;
- `<NavCards />` — every screen.

The [components folder](/blog/components) shows each of them at work, with its markup.
